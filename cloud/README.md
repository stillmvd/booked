# Booked Cloud

Личное облако игр для Booked и расширения Sorter 95: Cloudflare Worker (Hono) + D1. Хранит
текущее состояние игр f95 по номеру треда — решение, статус и звёзды Booked, версии, описание.
Закладки, папки и теги закладок, настройки Booked сюда не попадают.

Адрес: `https://booked-cloud.mozhno-sync.workers.dev`. Контракт API —
`Sorter 95/specs/001-triage-booked-sync/contracts/cloud-api.md`, поля — `data-model.md` там же.

## Команды

| Что | Команда |
|---|---|
| Тесты | `pnpm -C cloud test` |
| Типы | `pnpm -C cloud build` |
| Линт | `pnpm -C cloud lint` |
| Локальная база | `pnpm -C cloud migrate:local` |
| Локально | `pnpm -C cloud dev` — `http://127.0.0.1:8787`, ключ `dev` |

## Деплой

Аккаунт Cloudflare тот же, что у Waypoint (`wrangler login`, если сессии нет).

1. `pnpm -C cloud exec wrangler d1 create booked` — напечатанный `database_id` вписать в
   `wrangler.toml` вместо нулей.
2. `pnpm -C cloud migrate:remote`.
3. `pnpm -C cloud exec wrangler secret put API_TOKEN` — ключ вводит владелец сам. Ключ не
   записывать в файлы, чат и журналы; хранить в менеджере паролей.
4. `pnpm -C cloud deploy`.
5. Проверка: `curl -i https://booked-cloud.mozhno-sync.workers.dev/v1/health` без ключа —
   `404` с пустым телом; с ключом — `{ "ok": true, … }`.

Новый ключ: шаг 3, затем ввести его в Booked (Настройки → Облако) и в окне расширения.

## Устройство

- `src/app.ts` — ключ (`404` с пустым телом при неверном), лимит `LIMITER` 120 в минуту
  (`429` и `Retry-After: 60`), маршруты.
- `src/fields.ts` — проверка каждой правки по полям контракта.
- `src/merge.ts` — слияние «последняя правка по полю», будущее время обрезается до `now`,
  документ ≤ 8 КБ.
- `src/routes/changes.ts` — `seq` выдаётся внутри той же транзакции `DB.batch`, что и запись,
  upsert условный по прочитанному `seq`, при гонке строка перечитывается (до 3 раз).
- `src/cron.ts` — раз в сутки удаляет строки, помеченные удалёнными больше 30 дней назад, и
  поднимает `purged_before`.

## Отличия от контракта

- Пометка удаления хранится в `doc` как обычное поле `deleted: { v, at }`, чтобы спор
  «удалить / вернуть» решался тем же правилом последней правки. Наружу `GET /v1/games` его не
  отдаёт — клиент видит только `deleted_at`, как в контракте.
- Правка другого поля пометку удаления не снимает: строку возвращает только `deleted: false`.
  Контракт об этом молчит — клиенту, который «оживляет» удалённую игру (например, «Нравится»
  после «Убрать из списка» в Booked), нужно прислать `deleted: false` вместе с правкой.
- Ошибки разбора тела и параметров (`не JSON`, `since=-1`) — `400 { "error": … }`; контракт их
  не описывает.
